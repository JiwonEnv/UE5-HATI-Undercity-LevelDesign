# 커밋 규칙

실무에서 가장 널리 쓰는 [Conventional Commits](https://www.conventionalcommits.org/ko/v1.0.0/) 형식을 기본으로 하고, 언리얼 레벨디자인 프로젝트에 맞게 타입과 스코프를 정했습니다. **설명은 모두 한글로** 씁니다.

## 1. 형식

```
<타입>(<스코프>): <제목>

<본문>

<꼬리말>
```

예시:

```
feat(pcg): 쉘터 외부 바이옴 테스트 맵 추가

- Biome Sample 지형을 복사해 L_Dev_PCGBiome_Outdoor 생성
- Desert / Landslide / ConiferousForest 볼륨과 도로 제외 스플라인 배치
- 메시 바닥에서는 Get Landscape Data 때문에 생성되지 않는 점 확인

Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>
```

## 2. 타입

| 타입 | 언제 쓰나 | 예시 |
|---|---|---|
| `feat` | 새 기능, 새 맵, 새 구역, 새 기믹 | `feat(scene1): 하층 시장 구역 블록아웃 추가` |
| `fix` | 버그, 끼임, 뚫림, 충돌 문제 수정 | `fix(scene1): 계단 끝에서 캐릭터가 끼이는 문제 수정` |
| `level` | 이미 있는 레벨의 배치, 동선, 밸런스 조정 | `level(scene2): 엄폐물 간격을 400에서 300으로 조정` |
| `art` | 아트 패스: 메시 교체, 머티리얼, 라이팅, VFX | `art(scene1): 오염 구역 라이팅 색온도 변경` |
| `docs` | 문서만 바꿈 (README, 기획서, 이 문서) | `docs: 커밋 규칙 문서 추가` |
| `refactor` | 결과는 같고 구조만 바꿈 (폴더 정리, 이름 변경, BP 정리) | `refactor(bp): 문 BP를 공용 부모 클래스로 통합` |
| `perf` | 성능 개선 (드로우콜, LOD, 컬링, 스트리밍) | `perf(pcg): 바이옴 인스턴스 컬링 거리 축소` |
| `tools` | 에디터 스크립트, 자동화 도구 | `tools: 블록아웃 맵 재생성 스크립트 개선` |
| `chore` | 설정, 플러그인, 의존성 등 그 밖의 잡무 | `chore: PCG Biome 플러그인 활성화` |
| `revert` | 이전 커밋 되돌리기 | `revert: feat(scene1): 하층 시장 구역 블록아웃 추가` |

`level`, `art`, `tools`는 Conventional Commits 표준에는 없고, 이 프로젝트에서 추가한 타입입니다. 레벨디자인 작업은 "기능 추가(feat)"인지 "조정(level)"인지 구분해 두면 히스토리를 읽기 쉽습니다.

## 3. 스코프 (선택)

괄호 안에 **어디를 바꿨는지** 씁니다. 여러 곳이면 가장 중심이 되는 곳 하나만 쓰거나 생략합니다.

| 스코프 | 대상 |
|---|---|
| `scene1`, `scene2`, `scene3` | 씬별 레벨 (`Maps/Scenes`) |
| `dev` | 개발용 맵 (`Maps/Dev`: ScaleGym, Sandbox, 테스트 맵) |
| `blockout` | 블록아웃 머티리얼·메시·프리팹 |
| `pcg` | PCG 그래프, 바이옴 |
| `bp` | 블루프린트 |
| `char` | 캐릭터, 애니메이션 |
| `ui` | UI |
| `audio` | 사운드 |
| `config` | `.uproject`, `Config/*.ini` |

## 4. 제목 규칙

1. **한글로, 50자 이내**로 씁니다.
2. **명사형으로 끝냅니다**: `추가`, `수정`, `조정`, `삭제`, `변경`. ("추가함", "추가했습니다", "추가." ✕)
3. 끝에 마침표를 찍지 않습니다.
4. **무엇을 했는지**가 한눈에 보이게 씁니다. `수정`, `작업 중`, `업데이트`처럼 내용이 없는 제목은 쓰지 않습니다.
5. 에셋 이름, 맵 이름, 노드 이름 같은 고유명사는 영어 그대로 씁니다. 예: `L_Dev_PCGBiome`, `Get Landscape Data`

**제목만 읽고도 무엇을 했는지 바로 알 수 있어야 합니다.** 기준은 "이 커밋을 열어 보지 않아도 무엇이 바뀌었는지 알 수 있는가"입니다.

| ✕ 나쁜 예 | ○ 좋은 예 |
|---|---|
| `fix: 버그 수정` | `fix(scene1): 환기구 위에서 점프하면 벽을 뚫는 문제 수정` |
| `level: 맵 수정` | `level(scene2): 2층 저격 위치 엄폐물을 높이 150으로 변경` |
| `feat: 작업` | `feat(scene1): 하층 시장 입구 블록아웃 추가` |
| `art: 라이팅` | `art(scene3): 오염 구역 포그를 독성 초록색으로 변경` |
| `chore: 업데이트` | `chore(config): PCG Biome 플러그인 4종 활성화` |

## 5. 본문 규칙 (선택이지만 권장)

1. 제목과 본문 사이는 **한 줄 비웁니다**.
2. `-`로 항목을 나눠 씁니다. 한 줄은 72자 안팎에서 줄바꿈합니다.
3. **무엇을**보다 **왜**를 씁니다. 바뀐 파일 목록은 git이 보여 줍니다. 그 결정을 한 이유, 확인한 결과, 남은 문제를 적습니다.
4. 레벨 작업이면 **수치**를 남깁니다. 예: `점프 간격 500 → 400`, `복도 폭 300`

## 6. 꼬리말

| 꼬리말 | 용도 |
|---|---|
| `Co-Authored-By: 이름 <메일>` | 함께 작업한 사람 (AI 포함) |
| `Refs: #12` / `Closes: #12` | 관련 이슈, 해결한 이슈 |
| `BREAKING CHANGE: 설명` | 다른 맵이나 BP가 깨질 수 있는 변경 (에셋 이동, 이름 변경, 부모 클래스 변경 등) |

## 7. 커밋 단위

- **한 커밋에는 한 가지 목적만** 담습니다. 블록아웃 수정과 라이팅 변경은 따로 커밋합니다.
- 맵을 커밋할 때는 `.umap`과 함께 **`Content/__ExternalActors__/`, `Content/__ExternalObjects__/` 안의 해당 맵 폴더도 같이** 커밋합니다. World Partition 맵은 액터가 이 폴더에 따로 저장되기 때문에, 빠지면 맵이 비어 보입니다.
- 에셋 이름을 바꾸거나 옮겼다면 **Fix Up Redirectors**를 실행하고 같은 커밋에 넣습니다.
- 에디터가 저장하지 못한 파일(별표 표시)이 남아 있지 않은지 확인하고 커밋합니다.
- `Saved/`, `Intermediate/`, `DerivedDataCache/`는 `.gitignore`에 있어서 커밋되지 않습니다.

## 8. 브랜치 이름

`main`에 바로 커밋하지 않고 작업 브랜치를 만든 뒤 PR로 합칩니다.

```
<타입>/<짧은-설명>
```

예: `feat/scene1-market-blockout`, `fix/stair-collision`, `level/scene2-cover-spacing`

브랜치 이름은 영어 소문자와 하이픈(-)만 씁니다. 한글은 터미널과 일부 도구에서 깨질 수 있기 때문입니다.

## 9. 템플릿 사용

저장소 루트의 `.gitmessage`를 커밋 템플릿으로 등록하면, `git commit`을 할 때 편집기에 이 규칙 요약이 나타납니다.

```powershell
git config commit.template .gitmessage
```
